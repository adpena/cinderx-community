## Confirmed By Code/Test

- JIT preloading is explicitly documented as the phase where arbitrary Python execution is allowed.
  Source: [cinderx/Docs/Jit/preloading.md#L3](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/Docs/Jit/preloading.md#L3)
- `compile_func()` preloads dependencies, then compiles each target preloader.
  Source: [cinderx/Jit/pyjit.cpp#L3062](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/Jit/pyjit.cpp#L3062)
- The backend compilation step calls `jit_ctx->compiler().Compile(preloader)`.
  Source: [cinderx/Jit/pyjit.cpp#L3860](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/Jit/pyjit.cpp#L3860)
- CinderX installs frame evaluation via `_PyInterpreterState_SetEvalFrameFunc(..., Ci_EvalFrame)`.
  Source: [cinderx/Interpreter/interpreter_base.cpp#L50](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/Interpreter/interpreter_base.cpp#L50)
- Public extension entrypoints describe frame-evaluator install/remove semantics and safety caveats.
  Source: [cinderx/\_cinderx-lib.cpp#L925](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/_cinderx-lib.cpp#L925)
- Tests assert install/remove idempotence and JIT interactions (`auto`, `compile_after_n_calls`, `force_compile`, `lazy_compile`).
  Source: [cinderx/PythonLib/test_cinderx/test_frame_evaluator.py#L22](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/PythonLib/test_cinderx/test_frame_evaluator.py#L22)

## Inferred / Hypothesis

- Inference: preloading is the guardrail that separates side-effect-tolerant work from side-effect-intolerant compilation/lowering.

## Unknown Yet

- Batch-compilation scheduling quality under mixed static/dynamic workloads needs benchmark-backed analysis (Phase 3).
