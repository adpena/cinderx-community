## Confirmed By Code/Test

- Static Python is documented as a specialized bytecode compiler that uses type annotations and emits specialized opcodes.
  Source: [cinderx/Docs/StaticPython/README.md#L3](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/Docs/StaticPython/README.md#L3)
- The doc explicitly ties Static Python opcode specialization to JIT optimization and runtime checks.
  Source: [cinderx/Docs/StaticPython/README.md#L37](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/Docs/StaticPython/README.md#L37)
- Static/strict loader bootstrap calls `install_frame_evaluator()`, `watch_sys_modules()`, and `install_sp_audit_hook()`.
  Source: [cinderx/PythonLib/cinderx/compiler/strict/loader.py#L793](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/PythonLib/cinderx/compiler/strict/loader.py#L793)
- Runtime vectorcall dispatch checks `CI_CO_STATICALLY_COMPILED` and routes static functions through `Ci_StaticFunction_Vectorcall`.
  Source: [cinderx/Interpreter/interpreter_base.cpp#L21](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/Interpreter/interpreter_base.cpp#L21)
- Removing the frame evaluator is documented as dangerous because Static Python-compiled code may not run with default CPython evaluation.
  Source: [cinderx/\_cinderx-lib.cpp#L937](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/_cinderx-lib.cpp#L937)

## Inferred / Hypothesis

- Inference: Static Python correctness relies on tightly coupled compile-time assumptions plus runtime guard checks, rather than compile-time-only guarantees.

## Unknown Yet

- Exact guard-elision behavior under deeply nested static call graphs requires empirical tracing and benchmark evidence.
