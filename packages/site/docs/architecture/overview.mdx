## Confirmed By Code/Test

- CinderX declares JIT and Static Python as core features in upstream README.
  Source: [README.md#L16](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/README.md#L16)
- CinderX architecture states that Static Python uses a custom compiler and a modified interpreter loop.
  Source: [cinderx/AGENTS.md#L12](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/AGENTS.md#L12)
- Multi-version support is explicit via `PY_VERSION_HEX` and `Py_GIL_DISABLED`.
  Source: [cinderx/AGENTS.md#L23](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/AGENTS.md#L23)
- The `UpstreamBorrow` system is documented as the mechanism for copying selected CPython internals with provenance.
  Source: [cinderx/AGENTS.md#L31](https://github.com/facebookincubator/cinderx/blob/31bca9f3156b78cca3c6b36000c42c48f5ddf037/cinderx/AGENTS.md#L31)

## Inferred / Hypothesis

- Inference: the architecture intentionally separates stable public APIs from unstable CPython integration points to reduce fork pressure across Python versions.

## Unknown Yet

- Exact maintenance overhead per CPython release is not yet quantified.
- Cross-platform parity (especially macOS feature gaps) is partially documented but not fully traced subsystem-by-subsystem.
