# Good first issues

Use this guide to pick an issue that is easy to land and still high-value.

## Good first issue criteria in this repo

- Small, isolated change (single page, single command, or one adapter improvement)
- Source-backed docs updates or clear TODO/hypothesis marking
- No benchmark claim inflation
- Can be validated with:
  - `make lint`
  - `make test`
  - `make build`

## Good starter task ideas

- Add missing source citations to existing docs pages
- Improve compatibility checklist entries with reproducible commands
- Add benchmark metadata clarification text to docs/dashboard copy
- Improve developer ergonomics in `Makefile`/CLI help text

## How to self-assign and proceed

1. Open a feature issue and label intent clearly.
2. Share your implementation plan in 3-5 bullets.
3. Submit focused PR with validation output summary.
4. Mark assumptions explicitly if upstream behavior is uncertain.
